What is MarkinJS?

MarkinJS edits bounding boxes, polygons and keypoints on top of an image. You give it annotations as JSON, it draws them, people move and reshape them, and it hands the same JSON back after every edit. It has no dependencies and works with mouse, touch and pen.

It is an editor, not an application. Drawing tools, label pickers and model-assisted labeling belong to your app, built on the methods and events below.

Installation

npm install markinjs
import MarkinJS from 'markinjs';        // ES module
const MarkinJS = require('markinjs');   // CommonJS

Or with a script tag. Keep the version in the file name or URL, so an update is always a visible change:

<script src="https://unpkg.com/markinjs@0.4.0/dist/markin.min.js"></script>
<script src="/static/js/markin-0.4.0.min.js"></script>

Quick Start

<img id="photo" src="photo.jpg" alt="">
const editor = MarkinJS.create('photo', {
    annotations: [
        { id: 1, class_id: 0, bbox: [120, 80, 300, 220] }
    ],
    colors: { 0: '#2563eb', 1: '#16a34a' }
});

// One event after every completed edit, with the full list.
editor.on('change', (annotations) => {
    fetch('/api/images/42/annotations', { method: 'PUT', body: JSON.stringify(annotations) });
});

The Annotation Format

One object per thing in the image, in image pixels:

{
    "id": "a1",
    "class_id": 0,
    "bbox": [120, 80, 300, 220],
    "segments": [[130, 90], [400, 95], [410, 280], [140, 290]],
    "keypoints": [
        { "name": "head", "point": [260, 110], "v": 2 },
        { "name": "tail", "point": [300, 270], "v": 1 }
    ]
}
FieldMeaning
idString or number. Generated when missing. Always present in what MarkinJS returns.
class_idString or number. Picks the colour from options.colors. Class names stay in your app.
bbox[x, y, width, height].
segmentsOne polygon as [x, y] points, at least three.
keypointspoint is [x, y]. name is optional. v is COCO visibility: 0 not labelled (not drawn), 1 occluded (drawn dashed), 2 visible.

bbox, segments and keypoints are optional, but at least one must be present. Whatever MarkinJS returns, it accepts unchanged. Any other field (score, track_id, your own metadata) is carried through untouched, so saving the list from change never drops your data.

Coordinates normalised to 0-1 are a helper, not the default:

editor.getAnnotations({ normalize: true });        // fractions of the image size
MarkinJS.normalize(annotations, width, height);    // pixels -> fractions
MarkinJS.denormalize(annotations, width, height);  // fractions -> pixels

MarkinJS.create(target, options)

MarkinJS.create(target: SVGSVGElement | HTMLImageElement | string, options?: Options): Editor

target is an <img> or an <svg>, given as an element, an id or a CSS selector. It throws a TypeError if the target cannot be found.

  • An image: MarkinJS wraps it in a viewport and a stage (two <div>s) and lays an SVG over the picture as the browser draws it (borders, padding, object-fit and object-position are accounted for). The coordinate system is the image's natural size. destroy() puts the page back.
  • An SVG: MarkinJS draws into its own <g class="markin-layer">. The viewBox is the coordinate system and the area annotations stay inside. The SVG stays where it is: zooming changes its viewBox to the visible part of the image and nothing else.
  • Markup you own (a framework, or an SVG laid over a picture): mark the element that holds the picture and the SVG with data-markin-stage. Its parent is the viewport: MarkinJS zooms the picture inside it and changes nothing else.

Calling create() again on the same element replaces the earlier editor.

Data

MethodDescription
createAnnotation(annotation, { select = true })Add one. Returns its id, or null if the data is invalid.
updateAnnotation(id, patch)Merge patch into an annotation. A field set to null is removed. Returns true on success.
deleteAnnotation(id)Remove one.
addKeypoint(id, { name, point })Append a keypoint.
getAnnotation(id)A copy of one annotation, or null.
getAnnotations({ normalize = false })Copies of all annotations.
load(annotations)Replace everything. Starts a fresh undo history and does not emit change. Nothing is replaced unless every item is valid.
clear()Remove everything, as one undoable step.

Invalid input never throws and never changes anything: the method returns null or false and the reason is logged. Pass strict: true to get a TypeError instead.

Preview

MethodDescription
setPreview(shape)Show one shape that is not an annotation. setPreview(null) removes it. Returns false if the shape is invalid.

A preview is a shape that is shown on the image without being part of your data. Use it for anything temporary:

  • a suggestion the user can accept or ignore, from a model or from your own rules;
  • what a tool of yours would draw at the pointer, before the click that draws it;
  • a shape that is about to be pasted, imported or moved somewhere;
  • a highlight: the result of a search, or the item a list on your page points at.

shape has the fields of an annotation, in image pixels. Its bbox and its segments are drawn, dashed, in the colour of its class_id, and follow the view like everything else. There is one preview at a time, in an enabled or a disabled editor.

It is not data: it is not in getAnnotations(), emits no change and adds no undo step, so it is cheap to set as often as on every mouse move. Pointer events pass through it. load() and clear() leave it alone; it goes with setPreview(null), with destroy(), and when the <img> shows another picture. To keep one, pass the same shape to createAnnotation(). The preview example does that on a click.

Events

const stop = editor.on(type, listener);   stop();   editor.off(type, listener);
EventListener receivesWhen
change(annotations, { reason, ids })After every completed edit: create, update, delete, clear, undo, redo. Not after load().
select{ id, part, index, annotation }A part was selected.
deselect{ id, part, index }The selection was cleared or moved.
dragstart, drag{ id, part, index, handle, position, annotation }While dragging. Use drag for live read-outs.
dragendthe same plus changed, cancelledA drag ended. A change follows if something changed.
hover{ position, id, part, index }The pointer moved over the canvas (at most once per frame).
canvasclick{ position }A click that hit no annotation and was not a drag of the view.
viewchange{ x, y, width, height, scale }The view moved or the canvas changed size (at most once per frame). Also once for the first view.
viewsettle{ x, y, width, height, scale }The view has been still for settleDelay and shows another part of the image than when this last fired. Also for the first view, and for a new picture.

position is in image pixels. A listener that throws is reported and skipped; it cannot interrupt the editor. Subscribing to an event name that does not exist is reported, so a typo does not fail silently.

A listener may call back into the editor. createAnnotation() reports its change first and selects the new annotation after that, so a select listener can already edit or delete it.

A press on an annotation does not bubble as pointerdown or mousedown; listen for click, or for the editor's own select. A press on empty canvas bubbles as usual. The click that the browser sends when a drag of the view is released is swallowed.

A disabled editor still emits hover (with id: null) and canvasclick (for every click, wherever it lands).

Deletion rules

MarkinJS.create(img, {
    deletionRules: {
        bbox: ['polygon', 'keypoint'], // deleting the box deletes everything -> the annotation goes
        polygon: ['bbox'],             // deleting the polygon also deletes the box
        keypoint: []                   // deleting a keypoint deletes just that keypoint
    }
});

Those are the defaults. Exactly the listed parts are removed, 'annotation' removes the whole annotation, and an annotation left with no geometry is always removed.

Keyboard

KeyAction
Arrow keysMove the selection by 1 pixel. Shift: 10. Ctrl / Cmd: 0.2.
Delete, BackspaceDelete the selection.
Ctrl / Cmd + ZUndo.
Ctrl / Cmd + Shift + Z, Ctrl + YRedo.
EscapeCancel a drag, or deselect.
+, -Zoom in, zoom out.
Shift + 1, Shift + 0The whole image; the image at its real pixels.
Space (held)A drag moves the view, from anywhere.
n, pNext, previous annotation. Only with stepKeys: true.

Keys are ignored while the user types in an input, textarea, select or editable element, also inside web components. With several editors on a page, only the one the user last pressed on reacts; Space belongs to the editor the pointer is over. Holding an arrow key is a single undo step. A key is only taken when it does something.

The zoom keys also work in a disabled editor. keyboardControls: false switches every key off.

Zoom and Pan

The editor zooms and pans by itself. There is nothing to wire up.

InputAction
Trackpad pinch, Ctrl / Cmd + wheelZoom towards the pointer.
Wheel, two-finger scrollMove the view. With wheel: 'zoom': zoom towards the pointer.
Drag on empty canvasMove the view, once it is zoomed in (panOnEmpty).
Space + drag, middle-button dragMove the view from anywhere, also from on top of an annotation.
+ / -, Shift + 1, Shift + 0Zoom in / out, the whole image, real pixels.

The view goes from the whole image, as your page lays it out, up to maxScale screen pixels per image pixel. It stops a handle's width past the edges of the image, so a handle that sits on the edge can always be reached. A click still selects, and a drag of the view never selects or edits anything.

While the whole image is in view, a plain wheel is left to the page, which scrolls as usual. zoomControls: false switches all of this input off; the view methods keep working.

Work on the visible part

getView() can be used as a crop as it is. viewsettle is the moment for work that is too expensive to do on every movement, such as running a model on what is visible. 

let latest = 0;
editor.on('viewsettle', async (view) => {
    const request = ++latest;
    const result = await analyse(imageId, view); // your code: view.x, view.y, view.width, view.height
    if (request !== latest) return;              // the view has moved on since: drop this answer
    show(result);
});

What happens on your page

  • The SVG is never scaled. Zoomed in, its viewBox is the part of the image that is visible (with preserveAspectRatio="none"), so outlines and handles are drawn at the size they have on screen and stay sharp at every zoom, in every browser. Only the <img> under it is moved and scaled with a CSS transform. Ask getView() what is visible, not the attribute.
  • The box the image has on your page is the window. Zoomed in, the picture is clipped to it. At rest nothing is clipped and nothing is transformed.
  • An image that its own box crops (object-fit: cover) stays cropped: the view never shows more than your page shows at rest.
  • On a touch screen, one finger moves annotations and the view. Pinch is not handled yet: give touch users buttons that call zoomBy().
<!-- Markup you own: the marked element holds the picture and the SVG, its parent is the window -->
<div class="window">
    <div data-markin-stage style="position: relative; display: inline-block; line-height: 0">
        <img src="photo.jpg" alt="">
        <svg viewBox="0 0 1280 853" style="position: absolute; inset: 0; width: 100%; height: 100%"></svg>
    </div>
</div>

Recipes

Change the class of the selected annotation

const selection = editor.getSelection();
if (selection) editor.updateAnnotation(selection.id, { class_id: 3 });

Add a keypoint where the user clicks

editor.on('canvasclick', ({ position }) => {
    const selection = editor.getSelection();
    if (selection) {
        editor.addKeypoint(selection.id, { name: 'tip', point: [position.x, position.y], v: 2 });
    }
});

A click inside a box selects that box. Listen to select to place points there instead.

Show live coordinates

editor.on('hover', ({ position }) => {
    readout.textContent = `${Math.round(position.x)}, ${Math.round(position.y)}`;
});
editor.on('drag', ({ annotation }) => {
    if (annotation.bbox) sizeLabel.textContent = annotation.bbox.map(Math.round).join(', ');
});

Mark a keypoint as occluded

const { id, index, annotation } = editor.getSelection();
const keypoints = annotation.keypoints.map((kp, i) => (i === index ? { ...kp, v: 1 } : kp));
editor.updateAnnotation(id, { keypoints });

Hand the canvas to another tool for a while

editor.disable();   // nothing is edited; the view still zooms and moves
const stop = editor.on('canvasclick', ({ position }) => {
    addPoint(position.x, position.y);   // image pixels, at any zoom; never a drag of the view
});
// ...when your own drawing or model-assisted mode ends:
stop();
editor.enable();

Zoom buttons and a read-out

zoomIn.onclick = () => editor.zoomBy(1.5);
zoomOut.onclick = () => editor.zoomBy(1 / 1.5);
whole.onclick = () => editor.fit();
editor.on('viewchange', (view) => {
    readout.textContent = Math.round(view.scale * 100) + '%';
});

Go through the annotations one by one

next.onclick = () => { if (!editor.step(1)) say('That was the last one.'); };
previous.onclick = () => editor.step(-1);
// or leave it to the keyboard: MarkinJS.create(img, { stepKeys: true }) puts it on n and p

Draw a skeleton

MarkinJS.create(img, {
    annotations,
    skeleton: [['head', 'neck'], ['neck', 'left_hand'], ['neck', 'right_hand']],
    skeletonStyle: { strokeWidth: 2, strokeDasharray: '4 2' }
});
